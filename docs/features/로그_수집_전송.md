### 로그 수집 전송

- 기능 설명: 게임 로그와 Unity 콘솔 로그를 세션 단위 JSONL 파일로 기록하고, 프로그램 종료 시 gzip으로 압축해 로그 서버로 전송한다. 전송에 실패한 파일은 pending으로 보존해 다음 기동 때 재전송한다.
- 동작 조건 및 처리 흐름: RuntimeInitializeOnLoadMethod에서 GameLogger 싱글턴이 생성되고 logMessageReceivedThreaded로 콘솔 로그를 수집한다. 큐의 항목은 5초마다 persistentDataPath/Logs/{세션ID}.jsonl에 추가된다. 종료 시 wantsToQuit(플레이어)와 OnApplicationQuit(에디터 포함)에서 큐를 비우고 파일을 UploadBatch로 조립해 포그라운드 스레드에서 동기 HTTP로 전송한다. 서버 2xx 응답이면 파일을 삭제하고 실패하면 .pending으로 바꾼다. 다음 기동에서 남은 파일과 pending 파일을 endedCleanly=false로 재전송한다.
- 구현 상태: 구현·컴파일 확인 완료. 서버 연동 전송, 빌드 동작, 강제종료 재전송은 미확인.

#### 연결 및 협업

- 연결된 기능: 없음(독립 기능). 서버 측 수신기·처리기 계약은 docs/plans/로그_수집_전송_구현계획.md 3장과 5장을 따른다.
- 공유하는 코드 및 상태: MonoSingleton의 CurrentInstance와 _quitting 규약을 사용한다. persistentDataPath/Logs 폴더에 세션 파일을 만들며 유니티 기본 Player.log와는 별개다.
- 중복 또는 충돌 사항: 없음.
- 승인 필요 사항 및 결과: 서버 주소는 Inspector의 개발용·릴리즈용 두 필드로 분리하고 빌드 유형에 따라 자동 선택하도록 사용자 질문에 답변하며 확정했다. 실제 서버 주소 확정과 서버 구축은 별도 세션 작업이다.
