### 에코로케이션 및 적 감지

- 기능 설명: 소리의 월드 위치와 발생 볼륨을 적 청각 및 플레이어 임시 공간 인지에 함께 사용한다. Ctrl은 웅크리기 대신 일회성 발구르기 스캔이다.
- 동작 조건 및 처리 흐름:
  - 플레이어 상시 인지는 없다. 소리·스캔의 유효한 영역이 없는 공간은 전방·측방·후방 모두 숨긴다. 카메라 방향·플레이어 이동 위치는 자체 인지 영역을 만들지 않는다.
  - `SensoryManager.ReportSound(position, volume, source)`는 같은 소리 입력을 `StageSwordNoise`와 인지 마스크에 전달한다. 일반 소리 반경은 `Sound Radius × volume`이며 기본 Sound Radius는 4m다. 관측자에서 15m 이상 떨어진 소리는 플레이어 인지를 만들지 않는다. 설정 볼륨은 발생원 크기이며 옵션 믹서 음량과 분리한다. 일반 소리 반경은 Ctrl 스캔의 12m Wave 반경과 별개다.
  - 일반 소리는 즉시 원형 영역을 공개하며 발생 후 5초에 사라진다. 소리마다 위치·반경·발생 시각·확산 시간·유지 시간을 저장하고 겹침은 최대 가시성으로 표시한다. 기존 버퍼를 16→64개로 늘렸으며 가득 차면 가장 오래된 영역을 교체한다.
  - Ctrl의 좌·우 키, 기존 C 대체 키와 패드 B는 버튼의 새 눌림에서 한 번 `PlayerController.RequestScan`을 호출한다. 홀드 반복이나 토글은 없다. 구형 입력 어댑터에서도 Ctrl을 스캔에 연결하고 E 차지 입력은 유지한다.
  - 스캔은 충돌 캡슐 아래 지면을 검사하여 발 위치에서 기존 Wave를 생성한다. 기본 반경 0.25→12m, 확산 1.2초이며 동일한 SmoothStep으로 영역과 링을 확장한다. 확산이 끝난 뒤 영역을 추가 5초 유지하며 사라진다. 파동 인지가 즉시 전체 반경을 공개하지 않도록 스캔 소음의 일반 인지 생성은 생략한다.
  - 스캔은 기존 Footstep FMOD 음원을 볼륨 1.5·피치 0.75로 한 번 재생하고 같은 위치·볼륨을 적에게 전달한다. 행동 상태, 이동 속도, 캡슐 높이, 전투 상태, 공격 회복 시간은 변경하지 않는다.
  - 적 청각은 적별 Hearing Distance와 씬 소음 거리 상한 중 작은 값에 발생 볼륨을 곱한 직선 거리로 판정한다. 지면/NavMesh 위가 아닌 창문·등불 소리도 전달한다. 발생한 적 자신은 제외한다.
  - `HearNoise`는 방향과 청각 경계 종료 시각만 기록한다. 미발견 적은 순찰을 멈추고 기존 `EnemyMotor.FaceTarget`의 각속도로 회전한다. 소리만으로 Chasing/Searching에 진입하거나 마지막 시각 확인 위치·시간을 갱신하지 않는다.
  - 시각은 Detection Range, 수평 View Angle(기본 100도), 장애물 Raycast를 모두 통과해야 한다. 회전 이후 실제 시각 판정이 성공할 때 기존 추적·공격으로 전환한다. 시각을 잃은 뒤 기존 마지막 위치 수색·기억 만료 규칙은 유지한다.
  - 플레이어 발걸음의 기존 NoiseStrength, 일반 적·쌍둥이·보스 발걸음의 재생 볼륨을 같은 소음 경로에 전달한다. 발걸음은 원형 링을 추가 생성하지 않는다.
  - JapanWindow와 JapaneseHangingLamp 원본 프리팹에 기존 FMOD StudioEventEmitter와 AmbientSoundPerception을 연결한다. 기존 `event:/Ambience/Ambience` 반복음을 재사용하며 전용 창문·등불 음원은 현재 없다. 15m 안에서만 재생하고 거리 감쇠·좌우 패닝을 적용한다. 창문 볼륨 0.35, 등불 0.2이며 3초마다 소리 인지를 갱신한다. 중단 시 새 인지는 없고 마지막 영역은 자체 5초 수명으로 제거된다.
  - 인지 마스크는 TerrainMemory.RememberExpandingWave를 더 이상 호출하지 않는다. 윤곽선 셰이더는 방문/파동 기억 텍스처를 합성하지 않으므로 과거 방문 지형도 인지 만료 후 남지 않는다. 기존 TerrainMemory의 씬 직렬화와 세션 수명은 유지한다.
- 구현 상태: 코드·필요 프리팹·Ctrl 튜토리얼 문구 연결 완료. 최종 Unity 실행 검증 결과는 아래에 기록한다.

#### 연결 및 협업

- 연결된 기능: 감각 표현, 화면 공간 윤곽선, 적 추적, 플레이어 시스템, 패드 입력 및 튜토리얼 안내.
- 공유하는 코드 및 상태: 기존 Game.SensoryManager와 FMOD 음원·풀·파동 프리팹·EnemyMotor를 재사용한다. SoundManager 전투 믹싱과 공격 판정은 수정하지 않는다.
- 중복 또는 충돌 사항: 기존 웅크리기 반복 파동, 상시 주변 시야, 적 발소리의 인지 금지, 파동/방문 영구 기억 표시를 대체한다. 이전 명세의 해당 항목은 과거 기록이다.
- 승인 필요 사항 및 결과: 구현 전 기존 동작 대체 및 관련 명세 갱신을 질문했고 사용자가 승인했다. 테스트 코드는 작성하지 않는다. master 브랜치이므로 Git CLI·커밋·푸시는 사용하지 않는다.

#### 최초 구현 검증 (상시 시야 제거 전)

- Unity CLI 1.0.0-beta.11 / Unity 6000.3.22f1에서 런타임·Editor C# 컴파일의 Tundra build success와 현재 compiling=false·compilationFailed=false를 확인했다. CLI는 도메인 재로드 중 30초 제한/연결 재설정 오류가 있었으나 재로드 후 새 RequestScan과 AmbientSoundPerception 타입을 직접 실행했다.
- 셰이더 지원 true·컴파일 오류 0건을 확인하고 실제 GameView에서 실행했다. 기존 EdgeBetween 잠재 미초기화 경고 1건과 기존 KatanaDebugOverlay 미사용 필드 C# 경고는 수정하지 않았다.
- Stage_2 Play의 정상 Dynamic 입력/Update에서 임시 가상 키보드로 Ctrl 홀드→해제→다시 누름을 전달했다. 80개 포커스 프레임에서 스캔 2회, W 이동 속도 3.499658m/s, IsCrouching=false·상태 Free를 관찰했다. 입력 설정과 가상 장치는 정리했다. 실물 키보드/패드의 물리 입력 검증은 아니다.
- 스캔 요청 전후 Guarding 및 NormalAttack 상태가 각각 유지됐고 요청은 성공했다. 실제 발구르기 FMOD 재생 기록도 확인했다. 스피커를 통한 음향 청취·음색 평가는 미확인이다.
- 차폐된 소리 방향으로 실제 EnemyMotor가 회전한 뒤 angle=0·Idle·agent.isStopped=true·시각 false·마지막 시각 확인 -Infinity를 확인했다. 차폐 제거 후 Chasing·시각 true·이동 재개, 시야 범위 밖으로 대상 이동 후 Searching, 3.3초 뒤 시각 false·Patrolling 복귀를 확인했다. 볼륨 0.01의 범위 밖 소리는 청각 종료 시각을 변경하지 않았고 1.5 소리는 변경했다.
- CPU 인지에서 전방 1·후방 0·측방 0, 볼륨 0.25의 반경 3m에서 4m 바깥 가시성 0 및 볼륨 0.5의 반경 6m에서 4m 지점 가시성 1을 확인했다. 2초 간격의 두 소리는 4.81초 A=1/B=1, 5.12초 A=0/B=1, 후속 만료 뒤 A=0/B=0으로 독립적으로 종료됐다.
- 스캔 시작의 4m/8m 후방 지점은 0/0, 약 0.6초에는 1/0, 1.32초에는 8m=1, 5.93초에도 8m=1, 6.44초에는 8m=0·영역 수 0이었다. 기존 TerrainMemory 전역 상태가 켜진 씬에서도 인지 만료 뒤 지형이 남지 않았다.
- 실제 Stage_2 배치 등불의 FMOD playing=true, 거리 감쇠 음량 0.1651008, 위치·볼륨 0.2 소음 두 번의 간격 3초를 확인했다. 비활성화 후 재생 정지 및 마지막 소리 5초 경과 뒤 인지 0·영역 수 0을 확인했다.
- 실제 적의 NavMesh 이동 2.676m 동안 지면 접촉 3회·공통 소음 3회·볼륨 1.778279·인지 가시성 1·활성 파동 0을 확인했다.
- 최종 코드의 1920×1080 실제 GameView에서 스캔 전/중간/확산 후/유지/만료 5개 프레임을 캡처했다. 확산 후와 유지 프레임 및 스캔 전과 만료 프레임은 각각 픽셀 차이 0·유사도 100이었다. 해당 카메라의 2m 안에는 보이는 환경 경계가 없어 기본/만료 프레임은 검정이며, 스캔 동안 문·창문·방 경계가 표시된다.
- 추가 시각 검증은 같은 씬의 빈 공간에 런타임 전방·측방·8m 원거리 표식을 임시 배치하고 수행했다. 기본 상태에는 전방 표식만 보였으며 약 0.41초에 측방 표식과 지면 링이 나타나고 원거리 표식은 숨겨졌다. 1.32초에 원거리 표식도 보였고 5.93초에 유지, 6.44초에 기본 시야로 복귀했다. 기본/만료 캡처는 픽셀 차이 0이었다. 실제 링은 지면 위 Y=0.02·지름 6.903m·알파 0.728·Renderer 활성으로 관찰됐다. 임시 표식과 지면은 제거했고 씬/테스트 파일로 저장하지 않았다.
- 독립 소스·기능 검토에서 수정이 필요한 제품 결함은 없었다. 최초 화면 검토의 확산 경계 증거 부족은 위 전방/측방/원거리 표식 캡처로 보완했다.
- 검증 객체는 제거했고 Play를 종료해 런타임 위치·컴포넌트 변경을 복구했다. 열린 Stage_2는 import 이후 dirty 상태여서 저장하거나 재로드하지 않았다. 테스트 파일·검증 씬·Git CLI·커밋은 추가하지 않았다. 다른 씬의 전체 플레이, 실물 패드, 독립 Player 빌드 및 대량 동시 소리 성능은 미확인이다.
- C# LSP는 기존 설치 거절 상태이며 셰이더·프리팹 전용 LSP도 구성되어 있지 않다. Unity 컴파일·셰이더 import·실행 상태로 검증한다.

#### 2026-10-14 기본 무시야 및 소리 국소 인지 수정

- 사용자 재확인에 따라 전방 2m·40도 상시 영역 자체를 CPU와 셰이더에서 제거했다. 기존 Inspector 직렬화 값으로 상시 시야가 다시 켜지지 않도록 필드와 프리팹 값도 제거했다.
- 실제 Stage_1의 마스크가 켜진 PC_RPAsset 런타임에서 무음 전방 가시성 1을 재현했고 상시 반경을 0으로 바꾸면 0이 됐다. 일반 소리 배율 12m와 적 발소리 볼륨 1.7782794가 21.339m를 공개했으며 소리에서 10m 떨어진 지점도 표시됐다. 배율 4m로 바꾸면 해당 지점은 숨겨졌다.
- 일반 소리 배율만 12→4m로 변경했다. 적 발소리는 약 7.113m, 플레이어 기본 발소리 볼륨 0.6은 2.4m, 창문 0.35는 1.4m, 등불 0.2는 0.8m를 공개한다. 발생 위치·볼륨·개별 5초 수명은 그대로 사용한다. Ctrl 스캔 반경·확산·유지 시간과 적 AI는 변경하지 않았다.
